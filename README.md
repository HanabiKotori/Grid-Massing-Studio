# 场馆白膜 · Grid Massing Studio

基于 Vue 3 + Three.js 的场馆白膜（体量模型）在线生成工具。在地面网格上点选顶点画出场地平面，输入净高即可生成可交互的三维白膜体量；随后可在馆内绘制标准 / 脚手架 / 光地三种展台，摆放楼梯、洗手间、出入口、窗户、内墙以及座椅、沙发、茶几等家具，并以第一 / 第三人称方块角色漫游检查。

- 坐标单位为米；绘制与常规放置以 1 米网格为基准，家具自由落位、门窗参数支持更细粒度
- 数据纯前端保存，支持 JSON 导入 / 导出，便于与外部系统对接
- 默认使用浏览器本地 GPU 渲染，支持移动端与自动降级画质

## 功能概览

### 建模

| 对象 | 能力 |
| --- | --- |
| 场馆 | 多边形轮廓绘制、净高 2–24 m、封顶开关、半透明（X-Ray）查看、重新绘制；银灰金属墙面 + 共享 1K 法线贴图 |

| 合并 | 相邻展台可合并为一组，共享描边配色；可选统一高度或保留各自高度 |

### 场景与展示

- **分组工具栏**：视角（俯视 / 轴测 / 适配，快捷键 `T` / `I` / `F`）、显示（名称 / 刻度 / 面积 / 网格 / 底图）、画质（极致 / 高 / 中 / 低）、数据（汇报图 / 导入 / 导出）二级菜单在工具栏内部展开；显示 → 名称 还有第三级菜单，可分别开关「展台」和「基础设施」名称，初始化默认只显示展台名称。执行菜单操作后保持展开，便于连续调整，再次点击一级按钮或按 `Esc` 收起；打开天气 / 帮助 / 展示模式或进入漫游时自动关闭菜单。PC 竖向、移动端横向，移动端支持按内容宽度收起 / 展开，二级菜单过长时横向滚动。带指北罗盘、1 m 网格、尺寸刻度、展台名称与面积标注
- **自动保存与恢复**：场馆名称、场馆、展台、设施、底图、天气和太阳时间写入 IndexedDB，刷新或重新打开页面自动恢复；首次加载先查询本地数据，存在有效场景时显示加载遮罩并至少 2 秒后恢复，避免欢迎页闪现；没有有效场景则直接显示欢迎页，空场景记录不会误触发恢复等待；手动导入 JSON 时导入数据优先并覆盖自动保存
- **场馆名称**：点击左上角品牌标题可直接重命名，名称会进入场景 JSON、自动保存和汇报图
- **展示模式**：按 `S` 或从视角菜单进入，隐藏全部 UI 并缓慢环绕场馆；展台名称分布到馆外并用折线连接展台，基础设施名称隐藏，按 `Esc` 或右下角按钮退出
- **动态太阳**：可拖动的 24 小时时间轴，按真实时间流速推进并默认当前本地时间；支持播放 / 暂停与一键回到当前时间（约 0.9s 光照平滑过渡）。常规画质夜间使用自发光灯泡 + 烘焙地面光池，极致画质改用只向下发光的实时聚光灯
- **天气**：工具栏「天气」或 `Alt+W` 打开面板，`Alt+W` 只负责打开 / 关闭面板，不改变当前天气。切换天气时天空、雾和主光会用约 0.9 秒平滑过渡。面板顶部有天气效果总开关，关闭时默认为晴天；选择任意天气或应用实时天气后自动开启。顶部通过高德天气 API 查询实时天气，默认城市贵阳，也可输入城市名 / adcode；PC 端场馆首次生成或载入后会按上次查询城市自动应用实时天气，并在时间组件右侧显示当前天气；移动端默认不自动应用实时天气，可在面板中打开「使用实时天气」开关；启用后查询新城市会自动同步，关闭开关回到晴天。下方可分别拖动雨、雪、沙尘的粒子浓度（0–100%）和能见度，拖动时弹窗与遮罩暂时隐藏、只保留当前滑块方便预览，松开后恢复；拖动即时更新。当前天气没有对应粒子时提供状态提示和同类天气预览。桌面端为左右双栏，天气预设区域更大；移动端自动改为单栏，并可手动切换 13 种天气。天气联动天空、雾、太阳 / 补光强度、雨雪 / 沙尘粒子和雷暴闪光。晴、少云、多云时天空为天蓝色；少云和多云会绘制缓慢漂移的程序化云层。少云、多云和阴天同时使用程序化地面云影，云影会随风缓慢扫过地面，太阳主光同步轻微明暗变化；只在白天明显。第一人称漫游时额外叠加纯 CSS 镜头氛围层（边缘水痕、雾气、沙尘污渍、雷暴闪白），不增加 WebGL pass；天气只影响室外粒子，封闭顶棚内不会出现降水
- **汇报图**：数据菜单「汇报图」生成约 2400 × 1500 的高质量俯视 PNG，包含场馆名称、面积、覆盖率、展台名称、展商名称与编号；有 Logo 的展台会在各自左下角绘制带白色底板的高清 Logo 卡片，即使关闭展台名称也会导出；显示菜单中已打开的面积和刻度会一并导出，刻度使用 `L / W / H` 长宽高代号，并对重叠数字自动避让；导出时临时切换为清晰日光和图纸描边，不影响当前场景
- **方块角色漫游**：需要先生成场馆；进入选点时视角会先切到俯视并适配场馆大小，有顶场馆的顶板会临时半透明，进入或取消后恢复。第一人称低头可见方块身体和绿色准星，第三人称显示完整角色；第一人称移动时镜头带轻微上下、横向和滚转晃动，停止或切换第三人称后平滑归零；`P` 或工具栏进入漫游，`V` 或移动端按钮切换视角，带约 0.32s 平滑机位过渡；`R` 约 0.7s 返回起点；按住 `Alt` 临时释放鼠标；`F1` 打开帮助。WASD 移动、Shift 加速、空格跳跃、Esc 退出；第三人称镜头带墙体 / 展台遮挡收缩；靠近出入口可左键开合，门扇带缓动过渡；移动端提供虚拟摇杆、回到起点、跳跃按钮、工具栏折叠与横屏引导；移动端仅支持横屏漫游，检测到竖屏会立即退出漫游并提示旋转，漫游时罗盘位于时间组件左侧
- **漫游缩略地图**：PC 右下角、移动端时间组件下方显示场馆轮廓、展台、当前位置与朝向；漫游时自动隐藏编辑侧栏
- **自动巡游**：漫游中按 `E` 自动生成避开墙体与展台的路线，沿通道逐个展台停留约 6 秒并转向展台；PC 自动巡游栏位于底部操作提示上方，右上角显示当前展台的名称、展商、Logo（如上传）与面积，并预告下一站；行进中只保留下一站预告。`[` / `]` 调速，`L` 切换循环 / 单次，`U` 隐藏常规界面并保留巡游栏与当前 / 下一站信息（按任意键恢复），`WASD` / 空格或点击「接管」立即恢复手动。移动端控制位于顶部，巡游时隐藏摇杆，当前信息与下一站预告一起在右下角，点「接管」恢复手动
- **多人漫游**：工具栏「多人」或 `G` 进入 `/#/multiplayer` 路由，不加载编辑器。大厅显示在线玩家总数、在线房间与房间人数；房主从当前 IndexedDB 场景创建 2–8 人房间并生成邀请链接，客人通过链接加入后停留在房间页；房主开始漫游后，客人点击「开始漫游」才创建 Stage 进入。房间内所有玩家都可修改自己的名称和模型颜色。游戏内复用单人漫游的摇杆、操作提示、罗盘、缩略地图和自动巡游栏，缩略地图显示其他玩家位置，点玩家点可看名称，移动端可点开居中放大；房主额外保留时间栏与完整天气设置面板，时间进度与播放状态同步给客人；工具栏只保留显示 / 画质 / 天气。房间消息最多 200 字符，PC 按 `Y`、移动端点操作栏「消息」发送。房主可在等待房间玩家卡片、PC 漫游 Tab 玩家列表、移动端点击房间信息打开的玩家列表中踢出其他玩家，被踢玩家自动返回多人大厅。移动端仅支持横屏漫游，开始漫游时自动全屏并尝试锁定横屏；检测到竖屏会暂停并退出漫游状态，横屏后点击「继续漫游」，退出漫游或房间时自动退出全屏；客人由房主开始消息触发时若浏览器拦截自动全屏，会显示可手动重试的横屏 / 全屏提示，不支持全屏 API 时引导横屏操作。房间同步玩家位置、朝向、视角、自动巡游状态、出入口开关、天气及天气效果，服务端以 10 Hz 广播；昵称默认使用连接 IP，可在房间页修改并同步给所有人；玩家加入 / 退出会提示。漫游中按 `Tab` 可查看房间玩家列表并释放鼠标，再按 `Tab` / `Esc` 或点击关闭；PC 端在 1 米内对准其他玩家时，左键可击退对方并触发镜头晃动，按住右键拖动可拖拽对方，拖拽期间对方移动被锁定，互动位置会通过服务端同步，击退、拖拽开始和结束也会作为系统消息发送到房间消息流。点击「退出房间」会回到多人创建大厅，并移除 URL 中的旧房间号，左上「返回」才回到设计页；房主退出会解散房间，客人自动回到多人大厅而不是设计页；只有房主时房间保持。房主的房间场景只保存在服务内存，不持久化
- **编辑 / 预览模式**：预览模式（`render=1`）隐藏编辑面板、导入按钮与全部编辑快捷键，仅保留视图、导出与漫游，适合嵌入到其他系统做纯展示
- **画质分级**：极致 / 高 / 中 / 低四档；极致模式使用向下 180° 的实时场馆聚光灯、4096 阴影贴图与更高像素比，不使用烘焙光池；其余档位按 GPU 型号预判并在运行中根据帧率自动降级
- **应用内帮助**：工具栏 / 欢迎页「帮助」按钮或 `F1` 打开帮助；PC 使用分栏面板，并在顶部提供适配视图、网格、名称、面积、天气面板、进入漫游等快速设置，点击后自动关闭帮助并执行；移动端使用独立的全屏手风琴指南，内容按触屏、横屏和摇杆操作单独编写
- **欢迎页与结构面板**：未创建场景且启动检查完成后欢迎页水平居中，右侧场景结构隐藏；存在本地场景时先显示加载遮罩，不会先闪欢迎页；生成场馆后结构面板在 PC 端从右向左滑入，面积 / 覆盖率固定在顶部
- **示例场景**：一键载入内置 W1 场景（由当前 IndexedDB 场景导出，130 × 70 m，19 个展台 + 66 个设施，包含 25 扇窗户、16 段内墙、10 个出入口和 7 件家具；W1C01 为脚手架，咖啡洽谈区为光地，保留导出时的天气与太阳时间）；载入后会关闭名称显示并成为新的自动保存内容

### 编辑体验

- 撤销 / 重做（最多 60 步，连续操作 260 ms 内合并为一次）
- 展台 / 设施重叠校验、展台是否完全位于馆内的校验、轮廓自相交校验
- 家具需完整落在展台轮廓内；展台移动、旋转、缩放时家具会跟随，删除展台时自动清理其内部家具
- 选择家具进行摆放时，标准展台顶板与脚手架顶棚自动变为半透明，便于观察展台内部
- 展台与设施选中、面板定位、批量删除；主动选中展台 / 设施时自动展开对应卡片，等展开动画完成后再一次性滚动到条目；新增对象后保持新增按钮可见，便于连续添加，新增家具时定位到家具按钮组
- 基础设施支持 `Ctrl/Cmd` 相邻多选并整体拖动；只能加入与已选组贴边的设施，取消中间设施后若剩余对象断开会自动回到单选，门窗只能单独选择
- 基础设施列表按类型分组；家具先按所在展台、再按家具类型分组。分组可展开收起，选中设施时自动展开所属分组并显示数据；收起包含当前选中设施的分组会取消选中
- 选中一个或多个展台后按 `Ctrl/Cmd + C`，可连同展台内家具和落地设施一起复制，并进入半透明幽灵放置；选中单个基础设施后按 `Ctrl/Cmd + C`，也会保留尺寸、朝向、数量 / 开启状态和窗户离地高度进入放置；门窗继续吸附墙面，家具仍需在展台内。点击落位，`Esc` 取消
- **边缘吸附**：拖动展台或非家具设施、复制展台待放置、放置 / 复制非家具设施预览时，包围盒边缘靠近其他展台 / 设施约 0.5 m 内自动贴边；门窗沿墙靠近另一个门窗时按墙线区间吸附；吸附目标用橙色线框提示，贴边接触不会被视为重叠。家具拖动和放置均不吸附网格或边缘
- 按住空格进入纯视角浏览模式，右侧状态显示「浏览模式」，松开恢复「编辑模式」；画布同时给出浏览提示
- 右侧「场馆 / 展台 / 基础设施」卡片支持展开收起，带高度与透明度过渡；面积 / 覆盖率固定顶部，不随内容收缩
- 导入时对数据做容错与范围收敛，兼容旧字段

## 技术栈

- **Vue 3**（`<script setup>` + TypeScript，无状态管理库）
- **Vue Router**：hash 模式；`/#/` 编辑器、`/#/multiplayer` 多人漫游；邀请链接使用 `/#/multiplayer?room=房间号`
- **Three.js**：`WebGLRenderer`、`ExtrudeGeometry`、`OrbitControls`、`CSS2DRenderer`、`InstancedMesh`
- **polygon-clipping**：多边形求交 / 并集，用于重叠判定、合并轮廓与组选
- **Vite 7**：开发服务器与构建，`base: './'` 可直接部署到任意子路径

## 快速开始

环境要求：Node.js `^20.19.0` 或 `>=22.12.0`（Vite 7 要求）。

```bash
# 安装依赖（任选其一）
pnpm install
# npm install

# 启动开发服务器（默认 http://localhost:5173）
pnpm dev

# 类型检查 + 生产构建，输出到 dist/
pnpm build

# 本地预览构建产物
pnpm preview
```

### 多人漫游

多人漫游需要同时启动前端和 Node WebSocket 服务：

```bash
# 终端 1：Node 房间服务
cd multiplayerGame
npm install
cp .env.example .env
npm start

# 终端 2：前端
pnpm dev
```

项目根目录 `.env` 配置前端连接地址；生产环境使用 HTTPS 时必须使用 `wss://`：

```bash
VITE_MULTIPLAYER_WS_URL=ws://localhost:3010
```

完整环境变量、Nginx / 宝塔反向代理和 PM2 部署说明见 [`multiplayerGame/README.md`](./multiplayerGame/README.md)。

### 高德实时天气

在项目根目录 `.env.local` 中配置高德开放平台 Web 服务 Key：

```bash
VITE_AMAP_KEY=your_amap_web_service_key
```

可以复制 `.env.example` 作为模板。天气面板默认查询贵阳，支持输入城市名或 adcode；实时天气会映射到最接近的场景预设，手动天气仍然可用。

> 前端直连会把 Key 暴露在构建产物中，仅适合内部演示；正式部署建议通过服务端代理转发高德请求并限制 Key 的域名 / IP。

> 若 Windows 下 pnpm 报 `untrusted mount point` 或读取 `esbuild/package.json` 失败，这是卷不允许遍历 junction 导致的。项目已在 `pnpm-workspace.yaml` 中配置 `nodeLinker: hoisted` 与 `packageImportMethod: copy`，重新执行 `pnpm install` 即可改用无 junction 的平铺依赖布局。

## 使用流程

### 首次加载

1. 页面打开后先查询 IndexedDB 中的本地场景
2. 存在有效场景时显示全屏「正在加载场景」遮罩，保持约 2 秒后恢复场景；恢复完成前不会显示欢迎页
3. 没有有效场景时结束启动检查，显示欢迎页
4. 只有空场馆、空展台 / 设施数组的自动保存记录不会触发 2 秒等待，避免每次打开都被当成有场景

> 有效场景指至少包含场馆轮廓、展台、设施或底图之一。加载遮罩期间已挂载 Stage，但欢迎页、右侧结构面板和移动端面板按钮暂时隐藏。

### 建模流程

1. 点击「开始绘制」（或面板中的「绘制场地面积」），在网格交点上依次单击放置顶点
2. 点击起点、双击或按 Enter 闭合轮廓，在底部面板输入净高并生成场馆白膜
3. 在展台卡片选择「+ 标准 / + 脚手架 / + 光地」，在场馆内画出展台轮廓；前两者设定高度，光地直接生成微凸平台
4. 按需添加基础设施：出入口会自动吸附到最近的墙体或内墙上，并在墙上开洞
5. 添加家具：先在面板中点击「+ 圆座椅 / 扶手椅 / 沙发 / 圆茶几 / 方茶几」，再点击展台内部落位
6. 切换到「预览」或「漫游」检查结果，最后通过工具栏「导出」保存场景 JSON

> 绘制展台时场馆会自动半透明；场馆内部区域已扣除 0.4 m 墙厚与安全距离，展台必须完全落在该范围内。

> 需要对照原始平面图时，可先在场馆卡片上传底图，用 `Ctrl + 滚轮` 按 1 m 缩放、`Ctrl + 左键拖动` 按 1 m 移动对齐网格，再绘制场馆和展台。

### 分层说明

- `App.vue` 只负责创建状态与 composable、创建 Stage、注册生命周期和组合界面；业务规则分布在各 `use*` 模块
- `useEditorState` 是唯一状态源；`useSceneOperations` / `useBoothEditing` / `useInfraEditing` 处理编辑动作，`useScenePersistence` 处理存储与导入导出
- `sceneFile.ts` 与 `infraGeometry.ts` 不依赖 Vue，可独立测试；`useStageSync` 负责 Vue 状态到 Stage 的单向同步
- `Stage.ts` 不持有业务数据副本，通过 `setVenue / setBooths / setInfras / setScene` 接收数据重建图层，通过 `StageOptions` 回调把鼠标与漫游事件交回 Vue
- `build.ts` 只负责几何与材质，输入米制坐标，输出 `THREE.Group`
- `polygon.ts` 是纯函数库，便于单独测试或复用

## 场景 JSON 格式

导出文件形如 `grid-massing-YYYY-MM-DD-HH-mm-ss.json`：

```json
{
  "version": 1,
  "venueName": "W1 展馆",
  "weather": "cloudy",
  "weatherOn": true,
  "sunProgress": 0.5,
  "venue": {
    "points": [
      { "x": -65, "z": -35 },
      { "x": 65, "z": -35 },
      { "x": 65, "z": 35 },
      { "x": -65, "z": 35 }
    ],
    "height": 7,
    "ceiling": false
  },
  "booths": [
    {
      "id": "b1",
      "name": "展台 01",
      "exhibitor": "示例科技有限公司",
      "points": [{ "x": 0, "z": 0 }, { "x": 6, "z": 0 }, { "x": 6, "z": 4 }],
      "height": 3,
      "kind": "scaffold",
      "canopy": true,
      "groupId": "g1",
      "mark": "red",
      "logo": "<PNG base64，不含 data URL 前缀>",
      "data": { "externalId": "A-01" }
    }
  ],
  "infras": [
    {
      "id": "inf1",
      "kind": "gate",
      "name": "出入口 01",
      "x": -37,
      "z": 35,
      "rotation": 0,
      "width": 5,
      "depth": 0.5,
      "height": 4,
      "open": false,
      "openMode": "double"
    }
  ]
}
```

字段说明：

- `Pt`：`{ x, z }`，`x` 为东西向、`z` 为南北向，单位米
- `venue.ceiling`：是否封顶，默认 `false`（敞开便于查看内部）
- `underlay`：底图对象（`image` / `name` / `x` / `z` / `width` / `height` / `opacity` / `visible` / `locked`），也可为 `null`；导入时保持图片比例、套用最小尺寸并把位置取整到 1 m，尺寸和位置都不受网格限制
- `booths[].kind`：`massing`（默认）/ `scaffold` / `openfloor`
- `booths[].exhibitor`：可选展商名称，最多 60 字；显示在模型标签、Logo 立牌、汇报图中，并随 JSON / 自动保存保留
- `booths[].canopy`：仅脚手架展台有效，是否带顶棚，默认 `true`
- `booths[].noTop`：仅标准展台有效，`true` 表示去掉顶板与立柱、只保留围挡
- `booths[].mark`：`red` / `yellow` / `gray`；旧数据中的 `marked: true` 会按红色兼容
- `booths[].data`：任意业务字段，导入导出原样保留
- `infras[].kind`：`stairs` / `restroom` / `gate` / `window` / `elevator` / `wall` / `chair` / `armchair` / `sofa` / `table-round` / `table-square`
- `infras[].count`：仅电梯间有效，范围 1–6
- `infras[].open`：仅出入口有效，控制门扇开合
- `infras[].openMode`：仅出入口有效，`side`（侧开）/ `double`（对开）/ `up`（上卷，向上收进门楣）；缺省为 `double`
- 家具高度由类型固定；圆座椅固定 0.6 × 0.6 × 0.5 m，扶手椅固定 1 × 1 × 1.0 m（座高 0.5 m）；沙发高 1.2 m、方茶几高 0.5 m、圆茶几高 1 m，长宽可调
- 导入时会裁剪到合法范围（例如标准展台高度 0.4–8 m、场馆净高 2–24 m、光地高度固定 0.15 m），自动修正重复 id，并丢弃不在展台内部的家具

## 对外 JavaScript API

页面加载后可通过 `window.gridMassing` 与宿主系统对接：

```js
// 导出展台数组（深拷贝，logo 为纯 base64）
const booths = window.gridMassing.exportBooths()

// 导出完整场景（与「导出」按钮内容一致）
const scene = window.gridMassing.exportScene()

// 导入场景：支持 JSON 字符串或对象；返回是否成功
window.gridMassing.importScene(jsonText)

// 切换纯渲染（只读）模式
window.gridMassing.setRenderMode(true)
```

开发模式下还会在 `window.__stage`（Stage 实例）与 `window.__app`（响应式状态）上挂调试引用。

### URL 参数

| 参数 | 说明 |
| --- | --- |
| `?render=1` | 纯渲染 / 只读模式，隐藏编辑面板与导入按钮，禁用全部编辑快捷键 |
| `?mobile=1` | 强制按移动端交互（虚拟摇杆、竖屏提示） |
| `?quality=ultra\|high\|medium\|low` | 指定画质，同时关闭自动降级；`ultra` 为实时灯光极致模式 |
| `/#/multiplayer?room=房间号` | 直接打开多人页并自动加入指定房间，房间号为 6 位字母 / 数字 |

## 实现要点

- **墙体生成**：场馆轮廓先内缩墙厚（0.24 m）形成带孔洞的 `Shape` 再挤出；若存在出入口，则按墙段切分为墙垛 + 过梁 + 转角柱，保证开洞后仍然闭合
- **展台构造**：标准展台为四周带 2 m 居中缺口的围挡 + 闭合顶板；脚手架展台为 0.15 m 台板 + 加粗立柱（0.18–0.28 m）+ 顶部横梁（0.12–0.2 m）+ 可选顶板，台板以上架空。脚手架按面积估算柱距（约 4–10 m，目标约 10 个柱跨），自动在轮廓边界和内部布置立柱；内部网格线直接取边界柱坐标，保证立柱与顶部双向桁架对齐，光地展台同样为 0.15 m 台板。合并组只有全部为标准展台且高度一致时才会合并轮廓，其余按组着色、各自保留形态
- **Logo 定位**：标准展台沿轮廓每条边各贴一个 Logo，均位于该边外观视角的左下角；脚手架 / 光地仍为正面落地立牌，立牌落在 0.15 m 台面上
- **场馆材质**：银灰金属墙面使用 `public/textures/venue` 下的共享 1K 法线贴图与低饱和浅灰地面，只调整表面光照质感，不改变墙体 / 门洞结构；来源与许可见同目录 `sources.json`
- **展台材质**：标准 / 光地使用 `public/textures/booths/metal-normal.jpg` 的板缝法线；脚手架台板与顶棚继续用板缝法线，立柱 / 横梁单独使用 `brushed-normal.jpg` 拉丝金属法线，避免细金属件上出现板缝和铆钉。围挡、立柱和横梁的 BoxGeometry UV 按米制尺寸缩放，防止长条构件上的法线贴图被拉伸。来源与许可见同目录 `sources.json`
- **家具材质**：使用 `public/textures/furniture` 下的 1K CC0 颜色贴图，软包为浅冷灰细织物、椅背 / 桌面为石墨斜纹、框架 / 桌腿为低金属度灰缎金属；贴图按资源只加载一次，所有家具共享，ghost 预览不贴图。来源与许可见同目录 `sources.json`
- **重叠判定**：展台之间使用 `polygon-clipping` 的相交面积（> 0.02 m² 视为重叠，允许贴边拼接）；设施与家具之间使用分离轴定理（OBB）；家具额外校验整体轮廓是否落在同一展台内
- **性能**：常规画质场馆夜间照明使用一个 `InstancedMesh` 灯泡 + 烘焙好的 Canvas 光池贴图；极致画质改为最多 24 盏向下 180° 的实时 `SpotLight`，不生成光池。少云 / 多云的程序化云影使用一张 256px 可平铺纹理和一个透明地面层，不增加后处理 pass。`three` 单独分包；变更时只重建对应图层（`setVenue` / `setBooths` / `setInfras`）
- **P0 性能节流**：阴影贴图改为约 12.5 Hz 手动刷新；CSS2D 标签约 30 fps，罗盘约 20 fps；复用 `updateSun` 临时颜色，并在无粒子 / 无云影时跳过更新。保持画质档位、像素比、阴影分辨率和粒子数量不变
- **画质降级**：先按 GPU 名称预判，运行中每 90 帧统计平均帧时长，超过 26 ms 依次降为「中」「低」；低画质关闭实时阴影并降低像素比与灯位密度。极致档需手动选择，不参与自动降级
- **启动恢复**：读取 IndexedDB 后先判断是否有实际场景内容；有效时让启动遮罩至少展示 2000 ms 再应用场景，避免欢迎页闪现；空场景记录直接结束启动检查，不进入 2 秒恢复等待

## 部署

```bash
pnpm build
```

`dist/` 为纯静态产物，`vite.config.ts` 中 `base: './'` 使资源使用相对路径，可直接放到任意静态服务器或子目录下。构建时已开启 `vue-tsc` 类型检查，类型错误会导致构建失败。

项目使用 hash 路由，不依赖服务器做路径回退：

- `/#/`：编辑器
- `/#/multiplayer`：多人漫游大厅与房间
- `/#/multiplayer?room=房间号`：邀请链接

服务器只需正常提供 `index.html` 和静态资源，直接打开或刷新 hash 链接不会触发 Nginx 404，无需配置 `try_files`。

旧式 `/multiplayer` 路径和 `/multiplayer.html` 入口已不再使用，请使用 hash 地址。
