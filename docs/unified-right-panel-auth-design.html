01 / AUDIT
现状拆解

不是颜色问题，
是组件骨架不一致。

右栏用绝对定位 Tab + 子面板 padding 顶开；登录分别由云端存储和分享评论两个弹窗实现，所以标题、宽度、底部按钮和验证码比例都不同。

05 / STATES
状态规范

错误、加载、注册
都在同一张窗口里。

不新增另一套弹窗，不把错误变成系统 Toast；错误留在表单上方，提交按钮进入等待态。

01 / DEFAULT
默认登录用户名为空，密码为空，验证码加载完成；主按钮可用。
02 / REGISTER
注册模式多一行确认密码；主按钮文案变为「注册并登录」；验证码换新。
03 / ERROR
校验失败表单顶部红色窄条；验证码自动刷新；焦点回到用户名或错误字段。
04 / LOADING
提交中主按钮「请稍候…」并禁用；遮罩关闭禁用；成功后关闭弹窗。
TOKENS

统一尺寸

弹窗 430px；头部 18/20px；Tab 26px；输入 34px；验证码 16:9；主按钮 30px；底部 11/20px。分享页与编辑器共用。

A11Y

键盘与焦点

打开聚焦用户名；Tab 顺序固定；Enter 提交；Esc 关闭；提交中禁止关闭；错误使用 `role=alert`，不打断现有编辑器快捷键。

06 / DECISIONS
需要确认

登录设计先定这三点。

右栏已经按左侧方案调整；登录窗口等确认后再落代码。

Q.01 / WIDTH
统一宽度 430px？

推荐 430px。比当前分享窗口略宽、比云端窗口更窄，验证码 16:9 不挤压，桌面和移动端都好排。

Q.02 / FOOTER
底部统一为「取消 + 登录」？

推荐 是。不再使用全宽主按钮；两个入口的底部操作、键盘和等待态完全一致。

Q.03 / KICKER
保留云端 / 评论的英文 kicker？

推荐 保留但弱化：CLOUD STORAGE / REVIEW IDENTITY 只作为上下文标签，不抢标题层级。

Q.04 / EMPTY
评论空状态是否加「新增」按钮？

推荐 不加。空状态只解释为什么没有内容；新增仍由底部输入区和画布入口承担，避免重复 CTA。
