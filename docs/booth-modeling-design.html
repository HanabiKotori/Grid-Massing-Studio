01 / CURRENT
为什么现在加不动

不是展台太复杂，
是每个展台都太“独立”。

当前一个矩形标准展台约 20 个 Mesh；材质、几何、标签、Logo 纹理全部各自一份。任何单台修改都会触发整层 dispose + rebuild，raycast 也会递归所有子 Mesh。

矩形 4 × 4 m / 标准白膜阴影 pass 开销再翻倍
01
全量重建单台改色、改高度或改顶板，都会 disposeDeep 整层展台与全部标签、Logo 纹理。
02
零共享材质 / 零实例化每个展台新建 wall / floor / edge 材质，围挡每段独立 BoxGeometry，std 展台约 21 个对象，脚手架可达 40–100+。
03
拾取随对象数线性变慢每次 pointermove 递归 raycast 全部展台子 Mesh；100 台就是 2,000+ 对象。
04
标签没有裁剪100 台常驻 100 个名称 DOM + 100 条引线；没有距离、屏幕尺寸或聚簇策略。
05
颜色不是正式字段目前只有 mark / 合并组描边；没有 per-booth color，也没有进入场景 JSON、撤销和序列化白名单。
02 / PRINCIPLES
四条不动摇的规则

颜色是数据，
几何是批次，更新是局部的。

优化不是把展台做成一个不可编辑的黑盒。每个展台仍然有独立 id、颜色、高度、类型和 Logo，只是底层换一种更省的方式提交给 GPU。

04 / COLOR
保留自定义颜色

一个基色，
自动生成一套可读材质。

用户不需要分别调墙、顶、地、边线。选一个基色，系统派生明暗和边线对比；高级模式再开放边线颜色。每个展台的颜色独立保存。

COLOR SOURCE · 优先级
custom› mark› default

自定义色优先；没有自定义色时沿用旧 `mark` 红 / 黄 / 灰；都没有则使用默认白膜。合并组的 8 色只保留在结构树描边和组徽标，不再覆盖模型基色。

interface Booth { // ... color?: string // #rrggbb mark?: 'red' | 'yellow' | 'gray' groupId?: string }
`color` 必须同步进入 `readBooth`、`exportBoothList`、`sameBooths`；`sceneDiff` 用 JSON 比较，天然支持增量同步。

Q.01 / COLOR
颜色与标记的优先级？

推荐 custom › mark › default；mark 退化为编辑标记和角标，不再覆盖自定义基色。合并组色只用于结构树描边。

Q.02 / BATCH
一个 tile 多大？

推荐 40m × 40m，按场景规模动态合并。小场景 1–2 个批次，大场景 4–8 个 tile，避免每次改一台重建整馆。

Q.03 / ADD
一次最多生成多少？

推荐 200 台，二维网格、支持跳过冲突；阵列和命名一起提交。超过 80 台时自动提示开启 LOD / 简化标签。

Q.04 / SCAFFOLD
复杂脚手架要不要 LOD？

推荐 要：远景去掉内部桁架和重复边线，选中或近景恢复完整。否则 100 个脚手架仍会产生大量顶点。

RECOMMENDED SLICE

第一刀建议先做 Phase 01 + 02：颜色正式进数据，100 台标准展台切到 tile 合批。这个切片就能验证“颜色不丢 + 数量翻倍”的核心假设，再决定是否继续做增量更新和批量布展 UI。
