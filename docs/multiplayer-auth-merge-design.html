03 / AUTH
登录与连接

JWT 不直接进 WebSocket，
先换一次性票。

浏览器 WebSocket 不能设置 Authorization 头。用短时票代替长效 JWT，既避免 URL 暴露登录令牌，也能在 upgrade 阶段直接返回 401。

01 / LOGIN
云端账号登录多人页复用现有 JWT；无 token 显示登录门禁，不创建 WebSocket。
02 / TICKET
请求一次性票Bearer JWT → POST `/api/multiplayer/ticket`；服务端校验账号并签发 60s 票。
03 / UPGRADE
带票升级`/ws?ticket=...`；服务端原子消费票据，绑定 userId / username。
04 / ROOM
创建或加入原 `create` / `join` / `state` 协议不变；玩家身份来自账号。
已登录短时票升级成功房间

票据规则

32 字节随机值，服务端只存哈希；TTL 60 秒、单次使用、绑定 userId。房间内不再保存 JWT；票过期或重放直接关闭 1008。

失败状态

401 未登录 / 过期；429 票请求过频；403 Origin 不匹配；400 票无效或已使用；409 重复账号策略见待确认项。

多人页自己处理登录，不把场景甩回编辑器

邀请链接进入时保留 `?room=CODE`。用户登录成功后自动验证并加入原房间；房主场景仍在 sessionStorage，刷新和登录都不会丢失邀请码。

  • 编辑器点击「多人漫游」先检查登录；未登录可先打开登录窗口
  • 直接打开邀请链接：多人页显示登录门禁，登录后自动加入
  • token 过期：清 token、显示重新登录，连接不进入房间
  • 登录中不允许创建房间，避免匿名 socket 先占用连接

账号身份固定

房间内 `nickname` 默认等于账号用户名，服务端从 ticket 的 userId 取身份，客户端不能再伪造昵称。

  • 顶部始终显示账号名与在线状态
  • 玩家卡片使用账号名，不再出现 IP 地址
  • 仍可修改个人模型颜色
  • 房主 / 客人权限仍按连接上的 host 标记
  • 登录门禁复用统一 `AuthDialog`，不新增第三套登录 UI
  • 未登录时创建 / 加入按钮禁用，点击打开登录
STATE / UNAUTH

未登录

登录门禁覆盖大厅；不显示在线房间，不建立 socket。邀请码保留在 URL，登录后继续。

STATE / EXPIRED

登录过期

清理本地 token，显示“登录已过期”，关闭 socket；重新登录后重新请求票。

STATE / CONNECTED

已登录连接

顶部账号标签绿色；只有票验证成功后，才允许 `create` / `join` / `list`。

07 / RISK
风险与回滚

先保留回滚窗口，
再永久删目录。

房间不持久化，切换期间会丢失当前房间。建议发布窗口避开使用高峰；旧邀请链接登录后仍可继续使用房间码。

ROLLBACK

两小时回滚窗口

先部署新版 dataService（同时监听 /ws），再切 nginx `/ws` 到 3020；确认登录、创建、加入、广播都通过后，再停止 3010 并删除 gameService。

COMPATIBILITY

旧客户端直接断开

旧页面仍连 3010；切换时应同时发布新前端。旧邀请链接只保留房间号，用户刷新到新版本并登录后可重新加入。

SCALE

仍然单实例

房间和 ticket 都在进程内存；与现有 SSE 一样，多实例需要 Redis pub/sub。当前 2–8 人房间不需要拆服务。

SECURITY

不再暴露 3010

关闭安全组入站；只允许 nginx 访问 3020；WebSocket 校验 Origin、票、房间权限和 payload 上限。

08 / DECISIONS
需要确认

这四点决定实现形态。

设计默认值如下；确认后再开始改代码。

Q.01 / AUTH
连接票方案？

推荐 60 秒一次性票，不把长效 JWT 放进 WS URL，也不在首条消息前允许房间操作。

Q.02 / NAME
昵称固定账号名？

推荐 固定。多人页不再允许任意昵称，只保留颜色，避免冒充与身份漂移。

Q.03 / DUPLICATE
同账号多窗口？

推荐 允许，每个连接独立玩家，但显示名相同；后续可加“同一账号只保留一个连接”。

Q.04 / RECONNECT
断线自动重连？

推荐 本期不做。保留现有“断线回大厅”，先稳定迁移；重连涉及房间席位恢复，另立设计。
