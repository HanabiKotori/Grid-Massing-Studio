需求变更

只收口评论身份；链接分享、实时场景、编辑器回显、评论锚点全部保留。

01 / VIEW

查看保持公开

拿到链接即可打开 3D 场景、旋转缩放、点引脚定位，不需要登录。分享页不出现登录遮罩。

02 / COMMENT

评论必须登录

发表评论、回复、解决自己的评论都要求登录。未登录只保留只读的评论列表与定位。

03 / IDENTITY

匿名评论移除

不再填写昵称，不生成 authorToken。新评论使用云端账号的用户名与头像，服务端记录 user_id。

04 / LEGACY

历史匿名评论只读

已有匿名评论继续展示，标记「历史匿名」，不可回复；作者可在编辑器删除。

不改的部分：分享页 S-A 的 348px 常驻评论栏、编辑器 E-B 的 属性 / 评审 Tab、场景实时补丁、评论锚点跟随、链接冻结与撤销。

后端 / 接口

  • POST /comments 改为必须带 Bearer；作者从 JWT 取，不再接收 authorName / authorToken。
  • GET /comments 仍公开；带登录态时额外返回 mine，用于自己的评论操作。
  • PATCH / DELETE 使用 JWT 身份，仅作者本人或链接 owner 可操作。
  • allow_comment 继续作为链接级开关；关闭后登录用户也不能写。
  • 历史匿名评论保留 author_token，标记 legacy，只读。

前端

  • 分享页增加轻量登录弹窗，复用 /api/auth/login 与滑块验证码。
  • 登录 token 继续使用 gms.cloud.token；已登录的编辑器用户打开链接直接是评论态。
  • 未登录时评论栏只读；隐藏回复 / 解决 / 删除，保留定位。
  • 登录成功不刷新场景，保留相机、选中引脚、草稿与滚动位置。
  • 发布弹窗移除“允许匿名评论”，改为固定的“访问方式 / 评论权限”说明。

拍板点：登录用户是否允许解决自己的评论？本稿按“允许”设计；如果希望解决只由作者操作，只需把“解决”从登录访客的操作集中移除，其余布局不变。
