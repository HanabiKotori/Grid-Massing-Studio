Message architecture · type first

统一消息架构 · 按通知类型分流

统一的是路由、数据模型、队列和声音策略，不是把所有消息塞进一个收件箱。操作反馈走 Toast，协作消息回到评审 / 评论入口，系统状态留在状态栏，阻断错误用 Banner，表单错误留在字段旁，聊天留在房间消息。

类型划分

先按“用户需要怎么处理”分类，再决定放在哪里。类型是路由依据，不是颜色皮肤。

01 / ONE EVENT, ONE PRIMARY

一个事件只进一个主通道

评论进协作入口，保存进状态栏，校验留在字段。Toast 只做短反馈，不能成为第二个收件箱。

02 / CONTEXT FIRST

入口留在上下文里

编辑器用「评审」入口，分享页用评论抽屉 / FAB，多人用「房间消息」。不新增万能铃铛。

03 / PERSIST WHAT MATTERS

需要回看的消息不靠 Toast

评论、未读、连接中断必须能再次找到；Toast 只负责“刚刚发生了什么”。

A / ACTION

操作反馈

保存、复制、导出、发布成功 / 失败。短、可关闭、可选「撤销 / 重试」。

Toast · 2.4–5s · 无音效
B / COLLAB

协作消息

新评论、回复、作者回复、解决。进评审 / 评论入口，保留未读；必要时弹 Toast。

入口 + 未读 · 条件 Toast · 音效
C / SYSTEM

系统状态

自动保存、云端同步、SSE 重连、在线人数。持久、低干扰、不自动消失。

状态栏 / 细横幅 · 无音效
D / BLOCKER

阻断错误

链接撤销、服务不可用、空场景、权限失效。必须让用户看到并处理。

Banner / 全屏 · 可重试 · 无音效
E / FORM

表单校验

登录、发布、重命名、验证码。错误贴近字段，不要把用户甩到全局 Toast。

字段内联 · 无音效
F / CHAT

房间消息

聊天、系统提示、击退 / 拖拽通知。独立聊天流，不进入 Toast。

聊天流 · 未读 · 可选音效

为什么不做一个统一通知中心：评论已经天然属于评审 / 评论抽屉，聊天天然属于房间消息。再加一个铃铛会让用户在两处看同一件事。统一发生在底层，界面入口保持场景化。

统一路由

所有消息先进入 MessageCenter，再按类型、作用域、优先级和去重键分发；声音与 ARIA 作为消息属性，不绑在具体组件上。

移动端结构

协作通知在顶部，评论入口在底部

不使用右上角浮层压住模型，也不让 Toast 挡住评论抽屉。FAB 的红点 / 数字就是未读入口。

状态

动作反馈只在抽屉关闭时

评论已发送、复制链接等短反馈浮在 dock 上方；抽屉打开时只更新抽屉里的卡片和未读，不再叠一条 Toast。

无障碍

底部抽屉 + 顶部 Toast 都播报

协作通知 `aria-live=polite`；阻断错误 `role=alert`；抽屉打开时焦点进入，关闭时回到评论按钮。

组件库

同一个 ToastHost / NotificationCard / Banner 组件，按 type 切换颜色和语义；不要在页面里各写一套。

路由规则

类型决定主通道，状态决定是否弹、是否响、是否保留。不要用“页面”决定这一切。

规则行为原因边界
优先级D > C(错误) > B > A > F阻断问题必须先被看到同一时刻最多 3 条 Toast；B 不进 Toast 队列
去重相同 dedupeKey 2s 内合并SSE 爆发 / 多次点击不刷屏合并后显示数量，不重复播放声音
自己按 authorUserId 过滤不通知自己的评论 / 操作操作成功仍可有 A 类 Toast
面板状态B 仅在面板关闭或页面隐藏时弹 Toast面板打开时用户已能看到新卡片未读和「新」标记始终更新
声音仅 B 类，且页面隐藏 / 面板关闭声音只服务“有协作消息到达”A / C / D / E 不配音；F 可选
持久化B / C / D 不自动消失需要回看或处理A 自动消失；E 跟随字段
ARIAA/B/C 使用 polite；D 使用 assertive错误要打断，成功不打断F 使用 log；E 使用 describedby
演示模式A / B 全部静默，C 保留状态演示时不应有界面干扰D 阻断错误仍显示

复制规则

  • 标题写事件：「分享链接已复制」「王工 评论了 W1A03」
  • 正文给上下文：对象、位置、时间，不放整段评论
  • 动作明确：「查看」「重试」「撤销」「返回」
  • 避免重复：Toast 已经说过的，不在状态栏再说一遍

不做的事

  • 不新增万能通知收件箱；入口留在评审 / 评论 / 聊天
  • 不把校验错误做成 Toast
  • 不把聊天消息做成 Toast
  • 不让 B 类消息进入 A 类队列
  • 不对保存成功、校验失败、解决状态配音

拍板

这版建议先定 3 个方向；确认后再进入代码。

01 / ENTRY

不新增万能收件箱

编辑器用「评审」、分享页用评论抽屉 / FAB、多人用「房间消息」。统一发生在底层。

推荐 A · 上下文入口
02 / COLLAB TOAST

面板关闭时才弹

面板打开时插入卡片 + 未读 + 新标记；页面隐藏时弹 Toast / 未读。

推荐 A · 安静优先
03 / ACTION TOAST

底部居中，不抢画布

编辑器在时间轴上方，分享页在 dock 上方；错误可延长并带重试。

推荐 A · 底部锚点

推荐落地顺序：先抽出 MessageCenter + ToastHost（A 类），再补分享页 B 类通知与未读，随后把实时同步错误升到 C/D 类，最后接声音（S7 / S8）与移动端。这样不会一次性改动 170 个调用点，也不会在迁移期间出现两套声音。

备选方案：如果你希望“所有消息都能在一个地方回看”，可以在现有评审 / 评论入口上加一个「全部消息」筛选，而不是新增铃铛。这样仍保留上下文入口，同时满足统一收件箱的需求。
