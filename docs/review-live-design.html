需求汇总 / 一页看清

只保留已确认的范围。实时是默认能力，冻结版本作为归档补充。

角色

作者 / 访客

  • 作者：唯一可编辑模型；可发布 / 冻结链接、回复、解决、删除评论
  • 访客：只读模型；匿名昵称；可新增、回复、解决自己的评论
  • 不做多人同时编辑，不做访客漫游
实时链路

场景单向 + 评论双向

  • 作者编辑 → 增量 patch → 分享页 250 ms 内更新
  • 访客评论 → 作者未读 / 预览页 300 ms 内出现
  • 作者回复 / 解决 → 所有访客即时看到
链接模式

实时链接 / 冻结链接

  • 实时（默认）：跟随作者，不刷新
  • 冻结：发布时的快照，用于归档 / 验收
  • 两种链接共用评论表与锚点结构
回显

编辑器画布 + 属性栏

  • 画布引脚与对象位置同步
  • 右侧「属性 / 评审」Tab，未读角标
  • 新评论到达：角标 + 聚合提示，不抢焦点
非目标

多人同时编辑、访客漫游、口令与有效期、评论富文本 / 附件、跨项目评论。实时采用 SSE + REST，不引入 CRDT。

同步时序 / 三条链路

场景单向广播，评论双向同步；都用 SSE 下行 + REST 上行，断线后可全量恢复。

01 · 场景直播

作者编辑 → 访客

作者修改→ 250 ms 合并 diff→ PATCH /shares/:token/live→ revision + 1→ SSE scene.patch→ 访客增量更新
02 · 评论上行

访客评论 → 作者

访客发表→ POST /comments→ 持久化 + 分配 id→ SSE comment.created→ 作者未读 +1→ 卡片高亮 2 s
03 · 状态回传

作者回复 / 解决 → 访客

作者操作→ PATCH /comments/:id→ 更新状态→ SSE comment.updated→ 所有访客原地更新
04 · 断线恢复

重连 → 全量对齐

SSE 断开→ 重新申请 ticket→ GET scene?since=rev→ 返回 patch 或全量→ 恢复增量
单写者场景只有作者可写，无 OT / CRDT 幂等评论事件带 clientId，回显去重 降级SSE 不可用时 2 s 轮询，不阻塞编辑

前端改造点

  • Stage：单对象 upsert / remove，避免全量重建
  • 场景：diff、250 ms 合并、revision 冲突处理
  • 实时：SSE 客户端、ticket 刷新、重连与全量恢复
  • 评论：乐观更新、clientId 去重、未读游标
  • 锚点：对象相对偏移，移动 / 删除时重算
验收清单6 项
  1. 作者移动展台，分享页 250 ms 内跟随，相机与选中不跳。
  2. 访客新增评论，编辑器未读 +1，卡片高亮，但不抢焦点。
  3. 作者在编辑器回复 / 解决，分享页原地更新，无需刷新。
  4. 访客刷新或断网重连后，场景与评论回到最新状态。
  5. 评论随对象移动；对象删除后标记「锚点失效」，不漂移。
  6. 冻结版本不再跟随作者，评论仍可继续；实时链接可撤销。
